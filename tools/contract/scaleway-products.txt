# The Scaleway API products feint tracks, as <portal-slug>/<version>.
#
# Scaleway publishes one OpenAPI document per product, at
#   https://www.scaleway.com/en/developers/api/<slug>/<version>/schema.yml
# which is the "Download schema" link on each product page. There is no
# repository carrying them and no machine-readable index, so this list is the
# index — kept here rather than inline in mise.toml so that adding a product is
# one line and not a shell edit.
#
# The slug is the portal's, and it is NOT always the SDK package name. Measured:
#   baremetal -> elastic-metal
#   lb        -> load-balancer/zoned
#   k8s       -> kubernetes
# So a product added here has to be checked against its page rather than guessed
# from the Go SDK, and upstream:sync fails loudly on a 404 instead of leaving a
# stale file behind.
#
# When the slug and the SDK name differ, the line carries both: the portal path
# first (it names the download), the SDK's <package>/<version> second (it
# namespaces the contract, and the route check resolves operations under that
# name). A line with one field uses it for both, which is the common case.
#
# Restricted to the products the emulator has actually started, the same way the
# drift gate is: pulling all of Scaleway's surface would produce a contract
# describing an API nobody serves.

instance/v1
# instance/v2alpha1 holds the private-network-interfaces the Terraform provider
# has read since 2.81.0 (17 August 2026). Half the product moved: a NIC is still
# created through v1 by `scw`, and read through this by Terraform, so both
# documents are needed to check both halves.
instance/v2alpha1
vpc/v2
ipam/v1
iam/v1alpha1
marketplace/v2
block/v1
# The alpha is here because the CLI is: scw 2.56.3 calls /block/v1alpha1 for
# every block command while the Terraform provider calls /block/v1, so the
# emulator serves both and both must be checked against their own description.
# Measured on the first conformance run of SW-3, not assumed.
block/v1alpha1
# The Load Balancer's zoned API (#282). The portal path measured 2026-08-19:
# /en/developers/api/load-balancer/zoned/v1/schema.yml; the SDK calls the
# package lb and the routes live under /lb/v1/zones/.
load-balancer/zoned/v1 lb/v1
# The Public Gateway (#282). v2 only: the portal publishes no v1 document any
# more (measured 2026-08-19, /en/developers/api/public-gateway offers v2
# alone), which is why the whole vpcgw/v1 family is declined in the pack.
public-gateway/v2 vpcgw/v2
# The Account product's Project API (#372). The portal splits `account/v3` into
# two documents and neither is reachable at the SDK's own spelling: measured
# 2026-08-27, /en/developers/api/account/v3/schema.yml answers 404 while
# /en/developers/api/account/project/v3/schema.yml and
# /en/developers/api/account/contract/v3/schema.yml answer 200. Only the
# Project half is downloaded, because it is the half a client reaches: every
# third-party VPC stack evaluates `data "scaleway_account_project"` before any
# resource, and the ContractAPI signs subscription contracts, which is declined
# in the pack.
account/project/v3 account/v3
