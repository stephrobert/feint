# What you can validate against Feint

One question, answered in your vocabulary rather than this project's: **what can
I reasonably test against this emulator?**

Every row carries an anchor. A **yes** names the suite or the assertion that
proves it, a conditional row names the capability it keys on, and a **no** links
the section of [limits.md](limits.md) that says why. A row with nothing to point
at does not belong here, and a test refuses one
(`TestEveryConfidenceRowCarriesItsProof`).

This is the coarse view, for a human deciding whether to try. The fine view is
per operation and generated: [routes.md](routes.md) prints what every mounted
operation has earned — the generated block below carries the count — and
[`coverage/evidence.json`](../coverage/evidence.json) is the record it prints.

## How to read a verdict

**yes** means a real client drove it in the run that produced
[`coverage/evidence.json`](../coverage/evidence.json), and that the suite
asserted something about the answer. It does not mean every field of every
response is right: two defects sat behind a `driven` axis for months, which is
why the record publishes seven independent axes and never adds them into a score.

**with a runtime** means the control plane answers without one, and the claim
only holds when machines are real. Ask the emulator rather than guessing:

```bash
curl -s localhost:4599/_feint/health | jq .capabilities
```

A capability nobody declares reads as absent, deliberately, so a check skips
itself instead of asserting what no driver promised.

**no** is a decision with a reason, not a gap waiting to be filled by accident.
Each one links the section that states the cost. Several would change with work
somebody could do — fault injection, an opt-in identifier check, observable
transient states — and those are issues, not omissions.

## What this page is not

It is not a coverage percentage, and it deliberately carries no score. A single
number lets a weak claim ride on a strong one; that is the arithmetic version of
the overstatement this whole project exists to avoid. If you want the fine view,
it is per operation and it is generated.
