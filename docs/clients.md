# The clients a release was proved against

**Read this first if you pin.** This emulator's whole claim is that real clients
drive it. That claim is only ever true of the versions those clients had when
the suites ran, and this page is where they are written down — generated from
the workflow that installs them and from the fixtures that pin the providers,
never typed.

It exists because of one measured morning. A consumer running feint as a
required CI gate, with no credentials, resolves its Terraform providers fresh on
every pull request. Scaleway published provider 2.81.0 on 2026-08-17; it moved
private NICs from `instance/v1 · private_nics` onto
`instance/v2alpha1 · private-network-interfaces`, their `~> 2.68` constraint
picked it up the next morning, and their lane went red. They pinned back to
`~> 2.80.0` and wrote down what it cost: *the lane stopped emulating the
provider our clusters actually run.* Nothing we published would have let them
pin deliberately instead (#325).

## How to read it

A version in the first table is what the conformance workflow installs and
drives on every pull request. It is not a floor and not a recommendation: it is
the only version any claim in a release note is true of. A newer client is not
known to work until the pin moves and the suite passes on it.

The second table is the one that decides whether a Terraform lane will meet the
same emulator you did, and its third column is doing real work:

- **exact** — the constraint names one version. That version is what answered.
- **constraint** — `terraform init -upgrade` resolves it on the runner, on every
  run. It is a floor. The version that answered is not recorded anywhere in this
  repository, and this page will not pretend otherwise.
- **not pinned** — no constraint at all. Whatever the registry served that day.

The last column is derived from the conformance workflow and from
`tools/conformance/stacks.sh`, so a fixture nothing applies cannot pass for a
proof by sitting in the directory.

Read the third column narrowly, because it is the one a consumer pins against.
An **exact** constraint names the version that answered. A **constraint** is
resolved by `terraform init -upgrade` on the runner, every run, so the version
that answered is not knowable from this repository — it is a floor, not a
proof. **Not pinned** is not pinned: nothing here says which version ran, and
no number is invented to fill the cell.

## Where else this appears

The same block is spliced into the body of every GitHub Release, so the page and
the release say the same thing by construction. `feint docs --check` fails with
exit 2 the moment either drifts from the files above, which is how a generated
table stays a measurement rather than becoming a comment.
